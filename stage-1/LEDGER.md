## Rulings

Each ruling binds every seat. A seat that disagrees records dissent once, then applies it.

- **RL1.1 Runtime.** Python 3.12, one process, WebRouter called in-process (no helper process). Docker base `python:3.12-slim`; `requirements.txt` lists `webrouter[search,extract,research]>=0.12.0`. State is in memory behind a lock; builds run in background threads (a bounded pool). Do not use multiple worker processes (state must be consistent). Reason: simplest satisfying §2 and §11.
- **RL1.2 Layout.** `stage-1/Dockerfile`, `RUN.md`, `requirements.txt`, `.dockerignore` (excludes `acceptance/`, `LEDGER.md`), `src/dossier/server/` (P1, P2: builder-a), `src/dossier/engine/` (P3, P4: builder-b), `acceptance/` (prover). Unit tests: `src/tests/server/` (A), `src/tests/engine/` (B).
- **RL1.3 Engine contract.** `dossier.engine` exports `run_build(domain: str, cancel: threading.Event) -> BuildResult` where `BuildResult` is a dataclass `(ok: bool, spent_units: int, fields: dict[str, FieldResult])` and `FieldResult` is `(value: str|int|None, citations: list[dict(url, excerpt, provider)])`. `ok=False` means no provider call succeeded (state `failed`; the server then keeps old fields). `spent_units` counts every unit the build charged, also when `ok=False`. `fields` always carries all six keys. The engine never touches the clock, the HTTP layer or the store; it must tolerate `cancel` being set (stop early, return what it has). The engine never raises: any internal error yields `ok=False` with the units spent so far. Builder-a develops against a local fake engine (not committed) until builder-b's package lands; builder-b commits the real `dossier/engine/__init__.py` with the contract first (within its first commit).
- **RL1.4 Check order for write paths** (P2): 401 (token) → 400 `missing_idempotency_key` → 400 `malformed_request` for an unparseable or non-object body (POST /dossiers only) → 422 for an Idempotency-Key longer than 255 → resolve a claimed key (409 on a different body, 200 replay on the same) → field validation (wrong type 400, missing or invalid 422) → 404 (refresh without dossier) → effect.
- **RL1.5 Idempotency identity.** A claim is keyed by (user, key, method, raw path as sent, canonical JSON of the body with unknown fields removed). Only the `domain` field of the body counts for `POST /dossiers`. Raw path means exactly the path string sent (case preserved). A claim is stored only when the first response is 2xx; 4xx results store nothing. Concurrent requests with the same unused claim: the first runs, the others wait for it and return its stored response as 200 (if the first ended 4xx, the waiters re-run as first uses). Same key, same user, same method+path, different canonical body → 409. A refresh has no body, so the same key on the same path is always a replay.
- **RL1.6 Timestamps.** The clock holds the instant and the offset text of the last value set by reset or `POST /_test/clock`; responses print timestamps in that offset (`+00:00` when system time is used). `researched_at` equals the clock reading when the build's request was received.
- **RL1.7 Build states.** A dossier's `state` is `building` while a build runs; after a build, `ready` or `failed`. A dossier whose first build failed shows `failed` with six unknown fields, `researched_at` null. A failed later build leaves fields and `researched_at` of the last ready build. `spent_units` counts every build's charged units, including failed builds, and grows only when the build finishes or earlier (builder-a's choice; the value read after the build finishes must be exact). A refresh during a running build returns 202 `{dossier_id, domain, state: "building"}`.
- **RL1.8 Reset/import/export vs running builds.** Every reset and import bumps a state generation; a build started in an older generation sets its cancel event and its result is discarded. Export holds, for a dossier with a build running, the dossier as before that build began (fields, `researched_at`, `spent_units`, and state = outcome of its last completed build, `failed` with unknown fields when none). Export is a deep snapshot taken under the state lock. Import validates fully (track `"dossier"`, `format_version` 1 as integer, `state` object that the service can load) before touching state; failure → 422 with no change; invalid JSON or non-object → 400.
- **RL1.9 Validation corners.** Email uniqueness and login are case-insensitive on the whole email; the stored email keeps its case. `email` must have exactly one `@`, non-empty local part and domain, no whitespace. `display_name` is invalid when empty after trimming or longer than 100 characters. Password length is in characters. Wrong JSON type for any field → 400; missing field → 422; after type check, invalid format → 422. For signup, validation precedes the 409. Fixture: `now` required (missing → 422, wrong type → 400, unparseable or no explicit offset → 422); `users` optional; two users with the same email (case-insensitive) or the same id → 422 and no change. Reset and clock accept `Z` as an offset.
- **RL1.10 Listing.** `q` is matched as a lowercase substring of the normalised domain or of the `legal_name` value (not normalised itself). `limit`/`offset` must match `^[0-9]+$` (`limit` 1..200, `offset` ≥ 0); an empty value (`limit=`) is 422. Unknown query parameters ignored.
- **RL1.11 Non-object bodies.** An empty, unparseable, array or scalar body is 400 `malformed_request` for every JSON-body endpoint. Content-Type is not checked.
- **RL1.12 Evidence strategy (P4).** The build's goal is "known exactly when the evidence supports a value", so gather widely inside 80 units, with this fixed skeleton: exactly one error-free search whose query is the bare normalised domain (nimble, `lite` or `fast`); other searches use different queries naming the company (for example `"<Name> headquarters CEO"`); then Nimble `extract` (no `render`) of URLs found, to read the full served text, and one Nimble research run (25 units) asking all six fields, whose claims count only when the citation excerpt passes the support rule. Budget is reserved before each call (reserve = full table cost) and released only when the provider answers with an error status; a call whose answer does not arrive counts its full cost. Await all calls before deciding; never abandon a call that is still outstanding without charging it. Call timeouts ≥ 30 s each; hard cap 280 s per build; at most 80 reserved units. Mock `delay` faults of up to 10 s must not make a call fail. The first (and only counted) bare-domain search may be retried only after an error answer, never after a timeout. Tavily is optional; use it only if Nimble search is erroring and only for different queries.
- **RL1.13 Citations (P3,P4).** A citation excerpt is a single sentence from the page's prose that supports the chosen value, at most 500 characters, whitespace runs collapsed to one space, copied from text a provider returned for that URL (a search result's text, an extract's text, or a research citation's snippet). The citation's `provider` is the provider that served that text. A field with several supported values picks the value supported by the most distinct pages, ties broken by the value's ascending string form (numbers by numeric value), and cites up to 3 supporting excerpts (distinct pages first). Header lines and the `Facts:` line are never cited and never used to decide a value.
- **RL1.14 Task of the Prover.** Acceptance tests live in `stage-1/acceptance/` (pytest, black-box over HTTP, container run through Docker with the mock web). They are excluded from the image by `.dockerignore`.
