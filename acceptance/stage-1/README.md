# Stage 1 black-box acceptance

From this checkout, run `acceptance/stage-1/run.sh <commit>` (default `HEAD`). The runner builds the specified commit's `stage-1/` Dockerfile and the challenge mock web image, then starts four independent service containers, the mock and a Python test client on a private internal Docker network. The extra instances test cross-process import, the default port, and connection loss. Only Nimble is configured, as required. Docker and Python 3 are needed. The mock corpus defaults to `/home/ndivij/buildathon/sf-buildathon-2026/challenges/dossier/web`; override with `MOCK_WEB_DIR`. Published host ports default to 18200 and 18201; use `PROVER_PORT` and `PROVER_MOCK_PORT` to select distinct ports within 18200–18299. The client uses the isolated network directly, so host forwarding is not required. The runner holds `/tmp/factory-heavy.lock`, limits each service to 2 CPUs and 3 GiB, and cleans up its containers, images and network. No live credentials are used.

For an unmerged research-only handoff, `PROVER_RESEARCH_COMMIT=<research-commit> acceptance/stage-1/run.sh <base-commit>` overlays only `stage-1/app/research/` from that commit into the temporary Docker build context. Report both hashes: this is a composite test image, not either commit alone.

To run a named subset while investigating, set `PROVER_TEST_FILTER` to a `unittest -k` substring. The default runs all tests. A separate service uses a proxy that forwards each provider request to the mock and then drops its response, allowing the dependency's own log to measure the costs of lost answers.

Tests exercise only the HTTP interface and mock admin log. Assertions include requirement IDs. Failing individual cases do not prevent later tests from running. The mock key and call log are local test evidence; exports can contain secrets and are held in memory only.

Coverage limits: HTTP evidence alone cannot prove source provenance (R1.00), that every provider call used WebRouter (R1.07), or that a password was hashed rather than merely omitted from export (R1.68). The offline run cannot verify live-provider waiting rules (R1.84) or exhaust all possible company-naming searches (R1.43). The runner checks that RUN.md exists but does not execute its command (R1.03). The connection-loss proxy checks accounting when an answer is dropped after the mock records it; the 30-second timeout path remains a review item (R1.143). The five-second mock-delay case has a 300-second harness wait: expiry is inconclusive, not a prescribed deadline for a mock build with slow providers. Corpus value checks use L1.24's six published epoch-0 oracles; for the other six, citations are checked independently but completeness of their values is not scored. A passing test that reaches only one branch of a requirement is not evidence for every branch of that requirement.

Per L1.29, R1.02a and R1.69 are informative scope statements, not absence requirements; Gatekeeper reviews that in-scope behavior does not depend on those features. The dossier's exact field set is tested under R1.38 and R1.90.
